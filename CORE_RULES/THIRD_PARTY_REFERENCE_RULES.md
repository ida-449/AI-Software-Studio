# 第三方开源项目参考与知识产权规范

## 1. 允许行为

- 阅读公开仓库、官方文档、Issue、设计说明和许可证。
- 在 GitHub 允许且任务需要时 clone 仓库用于只读研究、验证或兼容性分析。
- 借鉴不受著作权保护的通用思想、流程、接口概念和工程模式，并以本工作室需求独立实现。
- 在知识库或设计记录中使用链接和简短归纳说明参考来源。

## 2. 引用或复用代码前

必须确认仓库许可证、目标文件许可证声明、版权归属、NOTICE 要求、修改与分发条件、专利条款及许可证兼容性。无法确认时不得复制代码。

任何实际代码、配置或大段文案复用必须：

1. 证明复用确有必要，优先选择独立实现。
2. 记录来源仓库、文件、commit、许可证和修改说明。
3. 保留许可证要求的版权、NOTICE 和署名。
4. 确认不会把第三方许可证义务错误扩散到业务代码。
5. 通过安全、依赖、供应链和维护风险检查。

## 3. 禁止行为

- 禁止把公开可见误认为无版权。
- 禁止复制许可证不明、仅供查看或商业限制内容。
- 禁止删除版权头、NOTICE、署名或许可证文件。
- 禁止仅替换变量名或改写表述来掩盖复制。
- 禁止把第三方密钥、样例账户、测试数据、素材或品牌资产带入工作室。
- 禁止因为可以 clone 就自动执行其安装脚本、二进制文件或网络操作。

## 4. 本轮参考项目

以下项目仅用于研究公开的通用工程机制，本轮实现未复制其代码或文案：

- OpenCode：工具执行、权限与会话治理。
- Claude Code：项目指令、Hooks 与任务生命周期。
- OpenAI Codex：沙箱、审批边界和自动验证。
- Goose：可扩展工具与执行闭环。
- Gemini CLI：策略化、可脚本化执行。
- OpenHands：隔离环境、事件证据和任务评测。
- Cline：计划/执行分离与检查点。
- Kilo Code：角色模式与任务编排。
- Qwen Code：终端代理与权限边界。
- Aider：Git 原生修改和 lint/test 修复循环。

项目链接与调研日期记录在 `KNOWLEDGE_BASE/ARCHITECTURE_PATTERNS/Executable_AI_Quality_Gates.md`。

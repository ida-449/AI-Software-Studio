# AI Software Studio 每日工作规范

## 目的

本规范将日常工程准备、质量检查和交付操作交由 AI 执行，最大限度减少非技术用户的手动工程操作。用户只负责提出业务目标、作出必要选择、完成必须由本人进行的授权，并反馈最终体验。

## 标准口令一：“开始今天的工作”

用户说出“开始今天的工作”后，AI 必须自动完成以下流程：

1. 识别当前设备，并确认 AI Software Studio 的绝对路径。
2. 若工作室不存在，从工作室配置的 GitHub 仓库自动 clone；若工作室已存在，检查 `remote` 是否指向配置仓库并执行 `git pull --ff-only`。
3. 检查工作室当前分支、上游分支、最新 commit 和 Git 状态；发现未知改动、分支异常或远端不一致时，先诊断再继续。
4. 读取 `PROJECTS/PROJECT_REGISTRY.md`，取得受管项目元数据。
5. 确认用户指定业务项目的实际绝对路径；不得以猜测路径代替检查。
6. 检查该项目的 Git 状态、当前分支与最新 commit、运行实例、环境依赖和昨日进度记录。
7. 输出简洁的开工报告，至少说明设备与路径、同步状态、项目状态、环境状态、昨日进度和今日可开始事项。

除身份授权、系统软件安装或高风险操作外，AI 不得要求用户执行命令。可由 AI 读取、诊断、配置或运行的常规工程操作均由 AI 完成。

## 标准口令二：“今天收工”

用户说出“今天收工”后，AI 必须自动完成以下流程：

1. 汇总本日完成内容、未完成事项和已知限制。
2. 根据项目技术栈自动识别并运行适用的自动测试、lint 和 build；如某项不适用或无法运行，明确记录原因，不得伪报通过。
3. 检查 Git 状态和完整 diff，并检查敏感文件、业务数据、密钥、凭据、环境文件及运行实例状态。
4. 更新项目状态和本次工作所必需的报告；不得为形式完整制造无价值文档。
5. 仅当测试通过且成果达到明确里程碑时，为业务代码生成 commit；纯文档规范可独立提交。
6. 按 `CORE_RULES/GIT_WORKFLOW_RULES.md` 的仓库分层策略处理版本：工作室自身安全检查通过后自动提交并推送；独立业务项目默认只做本地提交和本地备份。
7. 仅在本次工作形成可复用、可验证且未来仍有价值的经验时更新 `KNOWLEDGE_BASE`。
8. 输出简洁的收工报告，说明完成内容、验证结果、提交与推送状态、已知限制和是否需要用户决定。

## 收工同步分层

- AI Software Studio：完成状态、diff、测试和敏感信息检查后，AI 自动 commit 并 Push 到已验证远程。
- 独立业务项目：完成适用测试、状态更新、本地 commit 和本地备份；默认不得创建远程仓库、Push 或上传项目代码。
- 只有用户明确要求上传业务项目、创建项目远程仓库或推送到 GitHub，才允许进入远程同步；授权后仍必须完成敏感信息、未跟踪文件、大文件和完整 Git 历史审计。
- 任何风险未解决时，业务项目保持本地状态并阻断上传，不得删除用户数据来规避门禁。

## 异常处理

- 工作区存在未知改动时，保护现场并区分本次改动与既有改动，不得静默覆盖或提交。
- Git 冲突、权限异常、来源不明的运行实例或可能造成数据损失的操作，必须停止自动修改并先给出诊断和方案。
- 身份授权由用户本人完成；授权完成后，AI 必须自动继续余下步骤。

# 公众可用产品规则

## 1. 默认产品目标

用户创建 App、网站或其他数字产品的默认目标是让真实公众共同使用，而不是只在开发者电脑上运行。除非用户明确指定单机、内网或个人工具，`127.0.0.1` 只能作为开发与测试环境，不得视为产品交付完成。

## 2. 验证顺序

产品优先验证核心价值和直接体验：

1. 第一版优先做到打开即用，尽量不以注册、登录、安装或复杂配置阻挡首次体验。
2. 多人使用时必须保证数据归属清楚；无需账号时可使用匿名独立空间，并说明换设备、清除浏览器数据后的影响。
3. 注册、账号恢复和跨设备同步默认放在核心体验验证之后，只有长期身份、协作、付费、找回或合规需要出现时才建设。
4. 本地验证通过后，面向公众的产品必须进入公网交付准备，不得把启动命令交给最终用户。

## 3. 公网发布基线

- 提供可公开访问的 HTTPS 地址，并验证电脑、手机和平板浏览器的关键流程。
- 生产数据使用可靠持久化存储，明确备份、恢复、迁移和删除策略；不得依赖会随实例重启清空的临时磁盘。
- 区分本地、测试和生产环境；密钥与平台凭据不得进入源码、日志或 Git。
- 建立错误监控、健康检查、限流或滥用防护，以及可执行回滚方案。
- 对外说明匿名数据、Cookie、保留期限、清除方式和已知限制；涉及个人信息时升级隐私与合规要求。
- 公网冒烟测试和适用安全测试通过后，才向用户报告“其他人可以使用”。

## 4. AI 与用户边界

AI 负责部署方案、配置、构建、测试、故障诊断和发布验证。用户只需确认平台或费用选择、完成第三方登录授权、确认域名与正式公开发布，并进行最终体验验收。

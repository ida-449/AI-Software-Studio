# 多用户产品基线规范

## 1. 适用条件

当产品允许两个或以上用户注册、登录，或保存彼此独立的数据时，本规范自动成为强制规则。不得把单机演示、共享账号或仅依赖界面隐藏的方案认定为多用户产品。

## 2. 产品与架构基线

- 明确访客、普通用户、管理员及其他业务角色的权限边界，默认拒绝未授权访问。
- 账号必须具备注册、登录、退出、会话失效、找回访问权和注销流程；认证凭据不得明文存储或写入日志。
- 每条用户数据必须绑定不可伪造的所有者或租户标识；服务端对每次读取、修改、删除和导出执行授权校验，不信任客户端传入的身份。
- 多设备数据存放在受控的服务端持久化存储中，并定义迁移、备份、恢复、保留和删除策略；本地缓存不得成为唯一数据源。
- 面向多平台时优先提供响应式 HTTPS Web App；需要安装感和离线能力时增加 PWA。具体技术语言由业务、部署和维护约束决定。
- 区分开发、测试和生产环境；密钥使用环境变量或密钥服务管理，禁止进入源码、样例数据、日志和 Git 历史。
- 明确隐私告知、用户数据导出与删除、审计记录、限流和滥用防护；涉及法定合规时，在上线前完成专项确认。

## 3. 强制测试

多用户产品的完整质量门禁至少覆盖：

1. 注册、登录、退出、会话过期和账号恢复。
2. 用户 A 无法读取、修改、删除或推测用户 B 的任何私有数据，包括直接修改 URL、ID、请求体和 API 参数。
3. 各角色无法越权调用管理接口；未登录请求被拒绝。
4. 并发写入、重复提交、网络中断和重试不会造成数据串户或不可解释的重复数据。
5. 密钥、令牌、密码、个人信息不出现在响应错误、日志、报告和 Git diff 中。
6. 备份能够实际恢复，并验证迁移与回滚不会破坏用户归属关系。
7. 目标浏览器和移动端尺寸的关键流程可用；公开部署后执行 HTTPS 与生产冒烟测试。

任何跨用户越权、明文凭据、数据串户或不可恢复的数据丢失均为发布阻塞项，不得以“已知限制”方式放行。

## 4. 阶段交付要求

- PRD：定义用户类型、注册方式、公开范围、数据所有权、管理员能力和注销后数据处理。
- 技术设计：定义认证方案、授权模型、租户隔离、数据模型、会话、密钥、审计、备份恢复与部署边界。
- 风险评估：覆盖账号接管、撞库/暴力尝试、越权、数据泄露、滥用、隐私和第三方身份服务风险。
- 测试计划：提供至少两个隔离测试用户，执行正向、反向和跨用户访问测试。
- 发布报告：记录生产域名、认证与隔离测试、备份恢复证据、监控、回滚和剩余风险。

## 5. 用户确认边界

AI 负责方案、实现、测试和技术验收。只有以下事项需要用户本人确认：账号与品牌归属、第三方服务注册或登录授权、付费方案、域名与正式公开发布、隐私或合规承诺，以及最终体验验收。

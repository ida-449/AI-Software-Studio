# 报告管理规范

## 1. 目标

报告体系用于记录项目从需求确认到发布复盘的关键结论，使每个阶段的输入、输出、验收和风险均可追踪。

本规范只定义报告类型、目录和管理要求，不包含任何具体项目报告。

## 2. 必需报告

每个项目必须产生以下报告：

1. 需求报告。
2. 技术方案报告。
3. 测试报告。
4. 发布报告。
5. 项目复盘报告。

## 3. 报告内容要求

### 需求报告

必须说明项目背景、用户目标、需求范围、优先级和验收标准，并记录已经确认的需求结论。

### 技术方案报告

必须说明技术目标、系统架构、模块边界、数据与接口设计、技术选型、兼容性和风险控制方案。

### 测试报告

必须说明测试版本、环境、覆盖范围、执行结果、失败项、未覆盖项和剩余风险。

### 发布报告

必须说明版本号、修改内容、文件范围、测试与验收结果、已知问题、发布步骤和回滚方案。

### 项目复盘报告

必须说明项目目标、完成情况、遇到的问题、原因与解决方案、可复用经验和后续优化事项。

## 4. 目录分类

### PROJECT_REPORTS

保存需求报告和技术方案报告，以及反映项目阶段状态的综合报告。

### TEST_REPORTS

保存测试计划执行结果、自动化测试结果、回归测试结论和发布前检查报告。

### RELEASE_REPORTS

保存每个发布版本的发布报告、变更范围、已知问题和回滚信息。

### REVIEW_REPORTS

保存项目复盘报告、阶段评审结论和改进跟踪记录。

## 5. 命名与版本规则

1. 报告文件名应包含项目标识、报告类型和版本或日期。
2. 报告正文必须标明对应项目、版本、负责人角色、生成日期和状态。
3. 同一报告更新时应保留 Git 历史，不创建含义不清的重复副本。
4. 草稿、评审中、已确认和已归档状态必须明确标识。
5. 正式发布报告必须关联对应 Git commit 或版本标签。

## 6. 归档与质量要求

1. 报告必须基于实际执行结果，不得将未执行的检查标记为通过。
2. 报告中的结论、风险和未完成项必须清晰、真实、可追踪。
3. 项目完成后，应确认五类必需报告齐全并归入正确目录。
4. 不在报告中保存密钥、密码、个人敏感信息或临时调试数据。
5. 报告中的可复用经验应在复盘后按知识库管理规范进行沉淀。

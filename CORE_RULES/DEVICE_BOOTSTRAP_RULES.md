# AI Software Studio 设备初始化规范

## 目标

在新设备上由 AI 完成可自动化的工作室准备工作，使用户只参与系统级批准和身份授权。

## 标准流程

1. 识别当前设备和操作系统，确认目标目录的绝对路径。
2. 自动检查 Git 是否可用、版本是否满足需要、目标目录是否存在，以及当前账号对目标目录是否具备所需权限。
3. 若工作室不存在，从配置的 GitHub 仓库自动 clone AI Software Studio；若已存在，验证远端并安全同步。
4. 定位当前用户的 Codex 配置目录；若全局 `AGENTS.md` 缺失，使用 `TEMPLATES/GLOBAL_CODEX_AGENTS.md` 创建。若已存在，只合并缺少的老板模式规则，不覆盖未知用户规则，也不写死设备路径。
5. 检查工作室和已指定业务项目的依赖清单、运行时、包管理器、构建工具及版本要求。
6. 检查 GitHub CLI；若已安装，验证版本、登录状态和仓库访问权限。GitHub CLI 是工作室建议的标准依赖，用于身份验证、仓库验证和发布协作。
7. 输出设备初始化结果，包括路径、全局规则、Git 与 GitHub 状态、依赖状态、缺失项、风险和是否可开始工作。

## 自动化边界

- 能由 AI 检查、下载、配置、验证或运行的操作不得转交用户。
- 安装任何系统软件前，AI 必须说明软件用途、预计体积、权限影响和主要风险，并取得用户明确批准。
- 登录、OAuth、设备码和多因素认证由用户本人完成；AI 只提供必要提示，不索取密码或验证码。
- 用户完成登录授权后，AI 必须继续执行状态验证、仓库访问检查和余下初始化步骤。
- 涉及管理员权限、系统安全策略、数据删除、覆盖未知配置或其他高风险操作时，必须先说明影响并获得批准。

## 完成标准

仅当工作室路径有效、远端可信、仓库同步、必要依赖可用、访问权限验证完成且没有未说明的阻塞项时，才能报告设备初始化完成。

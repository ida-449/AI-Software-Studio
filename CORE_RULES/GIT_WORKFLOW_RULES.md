# AI Software Studio Git 自动化规范

## 默认职责

- `status`、`diff`、`add` 和 `commit` 默认由 AI 执行；`clone`、`pull` 和 `push` 必须服从下方仓库分层策略。
- 用户不负责手动输入常规 Git 命令；AI 应自行选择安全、非交互且可验证的命令完成工作。
- 遇到 OAuth、设备码或浏览器登录时，仅要求用户完成身份授权；授权后的验证和后续操作由 AI 继续。

## 仓库分层策略

### AI Software Studio

- 工作室自身完成状态、diff、适用测试和敏感信息检查后，由 AI 自动 commit 并 Push 到已验证的可信远程。
- 工作室仓库只允许保存通用规则、模板、项目元数据以及匿名、跨项目可复用的知识。

### 独立业务项目

- 默认完成适用测试、项目状态更新、本地 commit 和本地备份。
- 默认不得创建或配置远程仓库，不得 Push，不得以发布、收工、提交或备份为由上传项目代码。
- 只有用户明确说“上传这个项目”“创建项目远程仓库”或“把项目推送到 GitHub”时，才允许启动远程同步流程。
- 即使用户已明确授权上传，仍必须先通过下方远程上传审计；审计失败时保持本地状态并停止上传。

## 业务项目远程上传审计

上传前必须同时检查：

1. `.gitignore`、已跟踪文件、未跟踪文件和待提交 diff。
2. 当前树及完整 Git 历史中的密钥、令牌、账号、`auth/`、`data/`、登录状态、Cookie、Chrome Profile、真实业务数据和客户信息。
3. 大文件、真实素材、导出文件、日志、缓存以及不适合进入远程仓库的二进制资产。
4. 远程仓库的归属、可见性、写入权限、目标分支和将被推送的分支与标签。

发现任一风险时不得创建远程或 Push，不得通过删除用户数据、跳过历史或强制推送规避审计；必须先报告风险与最小安全方案。

## 同步与远端安全

- 操作前确认仓库绝对路径、当前分支、上游分支和远程地址。
- 拉取默认使用只允许快进的方式；发现分叉或冲突时停止自动修改，保护现场，诊断原因并向用户提出可选方案。
- 禁止强制推送，包括 `--force` 和 `--force-with-lease`。
- 禁止删除未知分支，禁止覆盖、重命名或移除未知远程配置。
- 未确认远端归属和写入权限前不得推送。

## 提交前检查

每次提交前，AI 必须：

1. 检查 Git 状态与完整 diff，只暂存本次任务范围内的文件。
2. 检查敏感文件、环境配置、密钥、令牌、账号信息、业务数据、导出数据和日志。
3. 检查相关运行实例，避免提交运行时临时文件、锁文件异常或未落盘状态。
4. 运行与变更范围相适用的自动测试、lint 和 build，并如实记录结果。
5. 确认提交信息准确描述本次里程碑，且不混入未知或无关改动。

只有测试通过且达到明确里程碑时才提交业务代码。纯文档规范不依赖业务构建结果，可以在内容检查通过后独立提交。

## 推送与结果验证

- 使用普通推送并建立明确的上游关系；不得通过改写历史绕过保护规则。
- 推送后核对本地 commit、远端 commit 和分支状态，确认 GitHub 已收到提交。
- 推送失败时先诊断认证、权限、网络、分支保护或远端变化，不得以破坏性命令解决。
- 最终报告必须说明提交哈希、分支、推送状态、测试结果和任何待用户决定事项。

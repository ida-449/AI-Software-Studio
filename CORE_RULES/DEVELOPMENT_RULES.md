# AI Software Studio 开发规范

## AI 开发标准流程

```text
需求提出
↓
需求澄清
↓
PRD
↓
技术方案
↓
风险评估
↓
开发计划
↓
编码
↓
自动测试
↓
AI自验收
↓
用户体验验收
↓
复盘沉淀
```

各阶段必须形成可检查的输出。当前阶段未满足进入条件时，不得跳过流程进入下一阶段。

## 1. 修改任何项目之前

必须确认：

- 当前路径。
- Git 状态。
- 当前版本。
- 运行实例。

如发现路径错误、工作区存在不明变更、版本不一致或运行实例可能受到影响，应先停止并完成诊断。

## 2. 修改代码之前

必须输出：

- 修改文件列表。
- 修改原因。
- 风险范围。

未经确认不得扩大修改范围，也不得修改与当前任务无关的模块。

## 3. 完成开发之后

必须输出：

- 修改文件列表。
- 测试结果。
- Git diff 摘要。
- 验收步骤。
- 已知风险。

输出应真实反映已完成的验证与未覆盖内容，不得将未执行的测试标记为通过。

## 4. 问题处理规则

遇到问题时不能直接修补，必须依次执行：

1. 定位原因。
2. 输出诊断。
3. 制定修复方案。
4. 再执行修改。

修复后还必须进行与影响范围相匹配的验证和回归测试。

## 5. 用户角色

用户是产品负责人，只负责提出需求和反馈体验结果。

需求澄清、方案设计、风险识别、代码检查、测试、问题定位和技术实现由 AI 团队负责，不将这些责任转移给用户。

# ClimbLog V0.1 产品需求文档

## 1. 产品概述

ClimbLog 是面向攀岩爱好者的本地训练记录助手。V0.1 以移动端优先的本地 Web 应用交付，帮助用户快速记录单条线路，并通过历史与统计分析观察成长过程。

## 2. 产品目标

- 降低训练记录成本，让用户愿意持续记录。
- 集中管理抱石与难度攀登的线路表现。
- 展示训练频率、完成率、难度分布和成长趋势。
- 全程本地运行，不连接外部接口，不上传训练数据。
- 提供简洁、美观、大方的移动端优先体验。

## 3. 目标用户

- 使用现代浏览器的攀岩爱好者。
- 同时参与抱石或难度攀登。
- 希望回顾训练并观察长期成长。
- 重视隐私，不需要账号、社交或云同步。

## 4. 核心使用场景

1. 训练时快速记录一条线路的类型、难度、结果和尝试次数。
2. 训练后补充地点、线路名称和备注。
3. 按日期、类型、状态或难度查找历史记录。
4. 按周期查看完成率、最高难度、难度分布和变化趋势。
5. 将本地数据导出备份，并在需要时从有效备份恢复。

## 5. V0.1 功能范围

### 5.1 线路记录

每条记录必须包含：

- 攀岩类型：抱石或难度攀登。
- 难度：从对应的固定难度表选择。
- 完成状态。
- 尝试次数。
- 记录时间。

可选字段：

- 地点。
- 线路名称或编号。
- 备注。

用户可以新增、查看、编辑和删除记录。删除前必须确认。

### 5.2 难度体系

- 抱石采用 V Scale。
- 难度攀登采用法国难度体系。
- 不允许自定义难度。
- 两套体系分别统计，不做跨体系换算或排序。

### 5.3 完成状态

| 类型 | 可用状态 |
| --- | --- |
| 抱石 | Flash、Send、Attempt |
| 难度攀登 | Onsight、Flash、Send、Attempt |

规则：

- Onsight 与 Flash 的尝试次数固定为 1。
- Send 的尝试次数不得小于 2。
- Attempt 的尝试次数不得小于 1。
- Onsight、Flash、Send 计为完成，Attempt 不计为完成。

### 5.4 历史记录

- 按日期倒序并分组展示。
- 支持查看详情、编辑和删除。
- 支持日期范围、攀岩类型、完成状态和难度筛选。
- 无数据或无匹配结果时展示明确空状态。

### 5.5 成长分析

支持最近 7 天、30 天、3 个月和全部时间，展示：

- 训练天数。
- 线路记录总数。
- 总尝试次数。
- 完成线路数和完成率。
- Onsight、Flash 数量及比例。
- 各难度尝试与完成分布。
- 两种攀岩类型各自的最高完成难度。
- 难度趋势及样本数量。

### 5.6 本地数据

- 使用浏览器本地数据库保存数据。
- 核心功能离线可用。
- 支持版本化 JSON 完整导出与完整恢复。
- 恢复前验证格式并要求用户确认。
- 不接入外部 API、广告、远程分析或账号系统。

## 6. 页面范围

- 首页：核心指标、最近记录和快速记录入口。
- 新增/编辑记录：在单页完成核心字段，次要字段默认收起。
- 历史记录：列表、筛选、详情、编辑和删除。
- 成长分析：时间范围、核心统计、难度分布和趋势。
- 数据管理：备份导出、恢复和本地数据风险说明。

## 7. 非功能需求

- 移动端优先，并适配现代桌面浏览器。
- 常规记录无需键盘输入，使用少量点击完成。
- 关键状态同时使用文字、图形和颜色表达。
- 数据操作失败时不得静默丢失或覆盖记录。
- 应用不依赖网络服务；构建后的静态资源可由本地服务器运行。
- 浏览器清除站点数据可能导致记录丢失，产品必须明确提示并提供备份入口。

## 8. 不做范围

- Android 原生或 iOS 原生应用。
- 外部接口、云存储和跨设备同步。
- 账号、社交、排行榜和在线线路库。
- 自定义难度体系。
- 视频分析、穿戴设备和 AI 训练计划。

## 9. 验收标准

- 用户能够合法创建、编辑、查看和删除两种攀岩记录。
- 难度体系、完成状态和尝试次数规则得到严格校验。
- 历史筛选和所有核心统计结果正确。
- 两套难度体系不会混合比较。
- 刷新或重新打开浏览器后已保存数据仍然存在。
- 有效备份可以恢复，无效备份不会破坏现有数据。
- 断网后核心记录、查询和分析能力仍可使用。
- 移动端常规记录流程简洁，界面视觉统一且可读。

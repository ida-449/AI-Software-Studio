# 批量自动化重复要求身份确认

## 问题现象

同一批次、同一浏览器会话、同一目标身份连续处理多个任务时，第一个任务确认成功，后续任务仍反复进入身份选择或人工确认页面。

## 原因分析

流程只缓存了“身份已确认”的布尔结果，没有保存后续导航所需的身份路由参数。每个任务又从无身份参数的新标签页进入业务列表，外部系统只能重新发起身份确认。

## 修复方案

1. 首个任务完成严格身份确认后，从已确认业务页记录身份路由参数。
2. 缓存必须按目标身份隔离，并绑定同一个 Browser Context。
3. 后续任务进入同一业务列表时复用身份路由参数，避免从无上下文地址重新导航。
4. 布尔信任、身份键、路由参数和 Browser Context 必须同时匹配才允许复用。
5. 页面明确重新出现选择器、显示其他身份或 Session 失效时，立即废弃缓存并按原安全门禁阻断或重新确认。

## 防止再次发生

- 测试覆盖首任务确认、后续任务复用、不同身份隔离、缺少可信状态回退以及明确冲突阻断。
- 批量任务不得只传递 `confirmed=true`；必须传递完成下一次确定性导航所需的最小上下文。
- 身份上下文只在当前批次和当前 Browser Context 内使用，不写入长期登录态或持久化配置。

## 适用范围

适用于多租户后台、代理商账户、组织空间、店铺主体和其他需要先选择业务身份的批量浏览器自动化。

# 动态表单控件可见但自动化误报不存在

## 问题现象

浏览器自动化进入动态编辑页后，人工可以看到目标业务区和操作控件，但脚本偶发立即报“未找到入口”。同一流程多次修改选择器后仍可能复发。

## 原因分析

1. 页面路由完成不等于业务表单已经异步渲染完成，一次性 DOM 扫描会把“尚未出现”误判为“不存在”。
2. 带图标、提示组件或包装节点的标签，其父元素 `textContent` 往往不是精确业务文本，完整元素文本匹配不稳定。
3. 直接执行 DOM `click()` 不等于真实用户点击，且如果不验证弹窗或页面阶段变化，无法证明动作生效。
4. 仅测试源码中存在某个选择器，不能覆盖动态渲染延迟和错误区域命中。

## 修复模式

对动态业务表单采用以下完整门禁：

1. 先确认正确页面或标签页所有权和路由。
2. 使用有最大超时的状态轮询，等待目标业务区真实渲染；禁止单次扫描后立即失败。
3. 用 `TreeWalker` 等方式匹配精确文本节点，避免父节点图标和附加文本污染。
4. 通过相邻业务标题或上下边界限定搜索区域，避免点击同名控件。
5. 将目标标记后交给 Playwright locator，先滚动到可视区域，再执行可信点击。
6. 点击后必须等待弹窗、路由或表单状态变化；未出现预期状态则判定失败。
7. 错误信息区分“等待渲染超时”“入口不存在”“点击后状态未变化”，便于下一次定位。
8. 操作前读取控件当前状态：未选时点击选项；已选且生成了配置卡片时点击卡片的编辑入口，禁止对已选控件重复执行选择动作。
9. 固定页头或透明覆盖层可能拦截普通点击。目标与业务区域已严格确认后，可使用带短超时的 Playwright 强制点击，并以弹窗或状态变化作为最终成功证据，禁止让自动重试持续滚动页面。
10. 页面存在多个同名控件时，必须使用目标标题后的最近业务分区标题作为下边界。禁止跨越中间分区寻找同名控件，也禁止在边界缺失时退化为固定像素范围。

## 防止再次发生

- 回归测试同时约束：文本节点定位、区域边界、状态等待、可信点击、点击后确认。
- 测试基准必须随定位策略更新，禁止继续断言已经淘汰的完整元素文本匹配。
- 人工可见但脚本不可见时，首先检查渲染时序、页面所有权和滚动容器，不先叠加更多宽泛选择器。
- 任何高风险或提交类动作都不得以“点击未抛异常”作为成功依据。
- 测试必须覆盖同一控件的未选、已选两种状态，以及覆盖层拦截普通点击的场景。
- 测试必须加入相邻分区同名控件的负向样例，并断言脚本不会点击目标分区之外的候选项。

## 验证结果

该模式已在一个动态第三方表单自动化问题中通过专项与全量回归测试。知识条目仅保留跨项目方法，不包含账户、产品、页面数据或外部系统身份信息。

## 适用范围

适用于 React/Vue 等异步渲染页面、弹窗表格、长表单、虚拟列表、跨标签页编辑流程，以及存在重复文案或复合标签的浏览器自动化。
